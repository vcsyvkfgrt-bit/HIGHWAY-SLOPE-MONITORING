# 监理例会材料自动化改造说明

## 已完成：第一阶段

本阶段目标是让平台具备“监理例会材料”这一类报告的基础生成能力。

已完成内容：

- 新增模板类型：`supervision_meeting`，前端显示为“监理例会”。
- 模板制作、Word/PDF 模板上传、模板选择流程均可选择“监理例会材料”。
- 新增监理例会专用占位符字典。
- 报告素材接口新增监理例会材料包：
  - `{监测对象概况表}`
  - `{本月监测进展清单}`
  - `{本月监测进展}`
  - `{分边坡监测进展}`
  - `{月度监测结论}`
  - `{月度工作建议}`
- 前端结构化素材支持 `section-list`，可按边坡展开小节。
- Word 导出支持 `section-list`，会按章节标题、分析文字、图表顺序输出。
- 已生成可上传测试模板：`docs/监理例会材料自动化模板.docx`。

## 当前实现边界

为了避免第一阶段直接大改数据库，本阶段优先复用现有数据：

- 边坡基础数据来自 `slopes`。
- 测点数量来自 `monitoring_points`。
- 地表变形、变化速率来自 `monitoring_data`。
- 深部测斜曲线来自 `inclinometer_surveys` 和 `inclinometer_survey_readings`。
- 预警、巡检、雨量沿用既有报告素材接口。

目前“边坡长度/坡高、左右幅、设计位移桩、设计沉降板、设计锚测力计、设计测斜管长度”等字段，系统还没有完整结构化台账，因此第一阶段只能用已维护测点数量和现有边坡字段生成概况表。

## 第二阶段建议

第二阶段建议补齐“监理例会材料”的台账字段，否则概况表仍会偏粗。

建议在边坡台账或单独的监理例会台账中增加：

- 边坡里程桩号
- 边坡长度
- 坡高
- 左幅/右幅/左侧/右侧
- 设计位移桩数量
- 设计沉降板数量
- 设计锚测力计数量
- 设计测斜管长度
- 当前施工状态
- 本月工作进展
- 是否纳入本月例会
- 例会展示排序

完成后，`{监测对象概况表}` 就可以从“已录入测点统计”升级为“设计数量 + 已实施数量 + 当前进展”的正式会议表。

## 第三阶段建议

第三阶段建议完善“结论和建议”的自动生成规则，让材料更接近人工编写质量。

建议规则：

- 地表变形：统计偏移增量、沉降增量、最大变化速率。
- 变化速率：默认参考值 `±2mm/d`，但应支持不同监测类型单独配置。
- 深部测斜：统计最大累计位移、最大相对位移、是否存在疑似拐点。
- 巡检问题：有问题时自动插入问题等级、位置、整改状态。
- 雨量响应：报告期有明显降雨时，自动生成雨量与变形响应描述。
- 结论分级：稳定、需关注、需复核、需预警。

建议保留人工确认环节，不建议让系统直接输出不可编辑的最终结论。

## 本次更新：第三阶段已补齐“施工与监控概况表”字段

本次已把监理例会材料中的“高边坡施工现状及监测工作进展”表格字段补到边坡台账，并接入 `{监测对象概况表}`：

- 边坡长度：`slope_length`
- 位置：`slope_position`
- 设计位移桩数量：`design_displacement_piles`
- 设计沉降板数量：`design_settlement_plates`
- 设计锚测力计数量：`design_anchor_dynamometers`
- 设计测斜管长度：`design_inclinometer_length`
- 当前施工状态：`construction_status`
- 本月/本期工作进展：`meeting_work_progress`
- 例会备注：`meeting_remark`
- 是否纳入例会材料：`include_in_meeting`
- 例会展示排序：`meeting_display_order`

生成 `{监测对象概况表}` 时，系统会优先使用这些人工维护的台账字段；未维护的数量字段由已录入监测点统计兜底。历史数据中坡高为 0 的边坡会按“未维护”处理，避免在正式表格中输出 `-/0`。
